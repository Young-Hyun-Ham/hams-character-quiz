# HAMS Character Quiz

좋아하는 캐릭터의 이름을 한글로 따라 쓰고, 도감 이미지를 가이드 삼아 직접 그리는 어린이용 놀이 학습 서비스입니다. 새로운 캐릭터 세계를 데이터 중심으로 추가할 수 있습니다.

## 주요 기능

- 캐릭터 도감 저장, 게임 스티커 획득과 스티커 상점 이용은 로그인한 사용자에게만 제공합니다. 비로그인 상태에서는 메인 헤더 아래에서 로그인을 안내합니다.
- 공통 헤더의 문의하기 오른쪽에서 HAMS SSO 로그인을 제공합니다. 로그인 후 이름 첫 글자 버튼을 누르면 이름·이메일·생년월일·성별·서비스사이트·요금제·AI 사용 상태와 회원정보수정·사이트변경·로그아웃 메뉴가 열립니다.
- 메인 화면의 캐릭터 세계를 누른 뒤 이름 퀴즈, 캐릭터 그리기, 목소리 사운드북, 게임하기 선택
- 게임하기는 3열 × 3행의 게임 선택 모달을 엽니다. 첫 번째 게임은 같은 그림 찾기이며, 나머지 8개는 준비 중입니다.
- 신비아파트의 GAME 02 `귀신 퇴치 비밀번호`는 부적의 덧셈·뺄셈으로 두 자리 비밀번호를 찾고 두 수 중 큰 수를 고릅니다. 첫 문제 정답이 도감 획득 확률(10~99%)이 되며, 완료 시 고스트 칩 스티커를 몬스터볼과 같은 50% 확률로 지급합니다.
- 티니핑·위시캣·시나모롤의 GAME 02 `마법 디저트 파티`는 두 접시의 디저트를 모아 10을 만들고 빠진 수 패턴을 맞힙니다. 첫 문제에서 찾은 수 하나당 5%를 도감 획득 확률로 적용하며 완료 스티커는 50% 확률로 지급합니다.
- 티니핑·위시캣·시나모롤의 GAME 03 `디저트 타임`은 아날로그 시계의 시침과 분침을 직접 드래그해 5분 단위 약속 시간을 맞힙니다. 겹친 경우 중앙의 시침과 가장자리의 분침을 나누어 잡을 수 있으며, 정답 후 도감 획득 확률은 20%로 고정됩니다.
- 신비아파트의 GAME 03 `마법의 비밀 지도`는 삼각형·사각형·동그라미·육각형·마름모·별·오각형·사다리꼴 조각을 같은 모양의 지도 빈칸에 드래그하거나 차례로 눌러 완성합니다. 지도 완성 후 도감은 1%, 스티커는 20% 확률로 획득합니다.
- 포켓몬의 GAME 03 `포켓몬 박사님의 가방 정리`는 무작위 포켓몬 3종을 이름별 바구니에 분류한 뒤 한 종류의 마릿수를 셉니다. 완료 후 도감은 1%, 스티커는 20% 확률로 획득합니다.
- 같은 그림 찾기를 누르면 레벨 선택 모달을 엽니다. 1단계는 4×4 카드 16장(8쌍), 2단계는 기존 6×6 카드 36장(18쌍), 3단계는 8×8 카드 64장(32쌍)입니다.
- 첫 카드는 두 번째 카드를 고를 때까지 계속 열어둡니다. 두 장을 고르면 약 1.2초간 비교하고, 서로 다른 그림일 때만 다시 숨깁니다. 같은 그림은 열린 상태로 남으며 단계별 완료 결과와 다시 게임하기를 제공합니다.
- 목소리 사운드북: 캐릭터 이미지를 누르면 반투명 모달에서 3초간 한국어 음성을 인식하고 이름을 채점
- 사운드북 이미지 영역 오른쪽 상단에 이름을 표시하며, 이름 전체에 무지개 7색 중 한 가지를 무작위 적용합니다. 글자 크기는 화면에 따라 16~24px이며, 한 줄 최대 6글자이고 공백에서는 줄을 바꿉니다. 같은 문제를 푸는 동안 색상은 유지됩니다.
- 음성 정답은 다음문제, 오답은 다시풀기·다음문제 제공. 완료 결과, 새로운 10문제와 오답 재학습 지원
- 전체 캐릭터 도감 검색, 더보기와 랜덤 캐릭터 선택
- 도감 이미지 가이드의 표시 여부와 진하기 조절
- 색상·굵기를 고르는 터치·마우스 Canvas 그리기와 PNG 저장
- 전체 도감에서 중복 없이 무작위 최대 10문제 출제
- 모바일 터치와 데스크톱 마우스를 지원하는 Canvas 필기
- 첫 글자 힌트와 브라우저 음성 합성을 이용한 이름 듣기
- 캐릭터를 클릭할 때마다 무작위 인사말을 보여주는 대화 말풍선
- 퀴즈 화면 진입 시 이벤트별 설정 확률에 따라 나타나는 깜짝 이벤트 모달
- 작성 획과 정답 윤곽의 정확도·완성도를 비교하는 로컬 채점
- 글자 모양 점수 95점 이상일 때 정답 처리
- 완료 후 점수·문항별 결과와 틀린 문제 재학습 제공

OCR이나 외부 채점 API를 사용하지 않습니다. 필기 이미지와 학습 결과는 서버로 전송하거나 저장하지 않고 브라우저 메모리에서만 처리합니다.

## 사용자 흐름

1. `/`에서 캐릭터 세계를 선택하고 모달에서 이름 퀴즈, 캐릭터 그리기, 목소리 사운드북 또는 게임하기를 고릅니다.
2. 퀴즈는 `/quiz/[slug]`에서 도감의 무작위 최대 10문제를 풀고 결과와 오답 재학습을 제공합니다.
3. 그리기는 `/draw/[slug]`에서 도감을 검색하거나 랜덤으로 친구를 고른 뒤 가이드 위에 그림을 그립니다.
4. 가이드를 끄고 완성된 그림을 확인하거나 흰 배경 PNG로 기기에 저장할 수 있습니다.
5. `/soundbook/[slug]`에서 이미지를 누르고 이름을 말합니다. 마이크가 켜진 시점부터 3초간 듣고, 인식 종료 후 띄어쓰기·문장부호를 제외한 이름 전체가 일치하면 정답입니다. 오답에서 다시 풀면 해당 문제의 최종 답변으로 결과를 집계합니다.
6. 게임하기 → 같은 그림 찾기 → 1·2·3단계를 선택하면 `/games/[slug]/memory?level=1|2|3`으로 이동합니다. 첫째·셋째 등 각 짝의 첫 카드는 계속 열어두고, 둘째·넷째 등 두 번째 카드까지 선택했을 때만 비교합니다. 다른 그림이면 두 장을 숨기고 같은 그림이면 찾은 짝으로 남깁니다. 비교 중에는 추가 카드 선택을 막습니다. 게임 고르기에서 단계를 바꾸면 새 카드판으로 시작하고, 처음부터·다시 게임하기는 현재 단계를 유지합니다. `level`이 없거나 올바르지 않으면 2단계로 시작합니다.

같은 그림 찾기는 선택한 카테고리에서 단계에 맞게 무작위로 8·18·32쌍을 구성합니다. 이미지가 필요한 쌍 수보다 적으면 일부 이미지를 짝 단위로 반복하며, 같은 이미지끼리는 원래 생성된 짝과 관계없이 정답입니다. 모바일에서도 단계별 4·6·8열을 유지하며 좁은 화면에서는 가로 스크롤로 카드를 볼 수 있습니다. 진행 정보는 브라우저 메모리에서만 유지됩니다.

### 음성 인식 환경

목소리 사운드북은 Web Speech API의 `SpeechRecognition` 또는 `webkitSpeechRecognition`을 사용합니다. HTTPS(개발 시 localhost), 마이크 권한, 음성 인식을 지원하는 브라우저가 필요합니다. 브라우저·기기의 지원과 서비스 연결 상태에 따라 동작 여부와 고유명사 인식 정확도가 달라집니다. 미지원, 권한 거부, 무음, 연결 오류는 오답으로 채점하지 않고 재시도를 안내합니다.

음성이 브라우저 제공자의 음성 인식 서버로 전송될 수 있으며, 이 사이트 자체 서버는 음성이나 인식 결과를 전송받거나 저장하지 않습니다. 이미지 분석 API 대신 도감에 연결된 정답 이름과 인식한 발화를 브라우저에서 비교합니다. [음성 인식 API 문서](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition)

## 기술 구성과 실행

### HAMS SSO 설정

설치된 `@hams-fam/sso-client`의 서버 handler를 사용합니다. 서비스 `.env`에 다음 값을 설정하고 서버를 다시 시작합니다.

```dotenv
NEXT_PUBLIC_APP_URL=http://localhost:3010
HAMS_OAUTH_SERVER_URL=http://localhost:3000
HAMS_OAUTH_CLIENT_ID=발급받은_Client_ID
HAMS_OAUTH_CLIENT_SECRET=발급받은_Client_Secret
HAMS_SESSION_SECRET=이_서비스만의_충분히_긴_난수
HAMS_COOKIE_PREFIX=hams_character_quiz
HAMS_SSO_SESSION_MAX_AGE_SEC=604800
NEXT_PUBLIC_DEV_MOCK_LOGIN=false
```

SSO 서버에 서비스의 Client ID·Client Secret과 콜백 주소 `http://localhost:3010/api/sso/callback`을 등록해야 합니다. 운영에서는 서비스 주소와 콜백 주소를 실제 HTTPS 주소로 함께 바꿉니다. `xxx` 같은 예시 값으로는 실제 SSO 인증을 완료할 수 없습니다. Secret은 서버 환경 변수에만 둡니다.

- `/api/sso/login`: 중앙 SSO로 이동하고 로그인 후 돌아올 현재 경로를 보관합니다.
- `/api/sso/callback`: 패키지가 state 검증·인증 코드 교환·HttpOnly 세션 및 암호화 토큰 쿠키 설정을 처리합니다.
- `/api/auth/me`: 헤더 회원 정보와 현재 서비스의 가입 정보를 반환하며 응답은 캐시하지 않습니다. 인증 토큰은 반환하지 않습니다.
- `/api/auth/profile`: 중앙 SSO 회원정보수정 또는 사이트변경 화면으로 이동합니다. 수정 후 서비스 로그인으로 돌아와 세션 정보를 갱신합니다.
- `/api/auth/logout`: 서비스 쿠키를 지우고 중앙 SSO 로그아웃으로 이동합니다.
- `/login`: 인증 요청 만료나 코드 교환 실패 시 재시도를 안내합니다.

로그인 여부와 관계없이 기존 놀이를 이용할 수 있습니다. 로그인·로그아웃 후에는 원래 페이지로 돌아가며, 헤더는 페이지 이동·탭 복귀 시 세션 상태를 다시 확인합니다. 로컬 모의 로그인이 필요할 때만 `NEXT_PUBLIC_DEV_MOCK_LOGIN=true`로 설정합니다. 이 옵션은 프로덕션에서는 비활성화됩니다.

빌드 후 `node --test scripts/test-sso.mjs`로 테스트용 SSO 서버를 이용한 로그인·콜백·세션·로그아웃 통합 검증을 실행할 수 있습니다. 실제 HAMS 계정이나 실제 Client Secret을 사용하지 않습니다.

## 채점 방식

채점 후 다시 쓰기를 누르면 기존 결과를 지우고 자동 채점하기로 돌아갑니다. 새 필기를 입력해야 채점 버튼이 활성화됩니다.

`quiz-game.tsx`는 정답 글자의 윤곽과 사용자가 그린 획을 오프스크린 Canvas에 렌더링합니다.

- 정확도: 작성 픽셀 중 정답 윤곽의 허용 범위에 들어온 비율
- 완성도: 정답 윤곽 중 작성 획의 허용 범위에 포함된 비율
- 최종 점수: `정확도 × 0.55 + 완성도 × 0.45`
- 정답 조건: 최종 점수 95점 이상, 정확도 45% 이상, 완성도 35% 이상

난이도는 `PASSING_SCORE` 상수로 관리합니다. Canvas 크기가 바뀌면 좌표 불일치를 막기 위해 작성 중인 획을 초기화합니다.

깜짝 이벤트는 `quiz-game.tsx`의 `QUIZ_EVENTS` 배열에서 관리합니다. 각 항목의 `probability`는 `0`부터 `1` 사이의 출현 확률이며, 전체 합계에 포함되지 않는 나머지 확률에는 모달이 표시되지 않습니다. 예를 들어 세 이벤트의 합이 `0.2`이면 화면 진입 시 전체 20% 확률로 이벤트 모달이 나타납니다.

## 데이터 관리

새 세계는 `app/data.ts`의 원본 배열에 `slug`, 한글·영문 제목, 설명, 테마 색상, 표지와 `characters`를 추가합니다. 각 캐릭터에는 `name`, `image`, `hint`가 필요하고 티니핑에는 `season`도 필요합니다. `slug`와 이름 중복, 첫 글자 힌트, 로컬 이미지 존재 여부를 확인합니다. 목록 확장은 홈과 정적 경로 생성에 자동 반영됩니다.

포켓몬 데이터는 생성 파일을 직접 수정하지 않고 다음 명령으로 갱신합니다.

```bash
pnpm pokemon:sync
```

공식 도감 응답을 번호순으로 수집하며 1,000마리 미만이면 파일을 만들지 않습니다. 네트워크 연결이 필요합니다.

위시캣 이미지는 도감 PDF의 위시캣 페이지에서 이름 순서대로 추출하며, 캐릭터 내부의 흰색은 보존하고 가장자리와 연결된 흰 배경만 투명하게 처리합니다.

```bash
node scripts/extract-wishcat-assets.mjs
```

티니핑 이미지를 재처리할 때는 다음 명령을 사용합니다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts\remove-teenieping-white-background.ps1
```

스크립트는 `public/teenieping/catalog-copy/*.jpg`를 원본으로 기대하고 `public/teenieping/catalog/*.png`를 만듭니다. 현재 저장소에는 `catalog-copy`가 없으므로 실행 전 원본 폴더를 준비해야 합니다. 이미 투명한 PNG 데이터가 `.jpg` 확장자로 저장된 경우 알파를 보존하고, 실제 JPEG는 외곽과 연결된 흰 배경만 제거합니다.

## 문의 게시판

문의글은 Firestore의 `inquiries` 컬렉션에 저장하며 제목, 200자 이하의 내용, 최대 5개의 문자열 태그와 댓글 수를 가집니다. 댓글은 각 문의글의 `comments` 하위 컬렉션에 저장하고 `parentId`로 부모 댓글을 연결하므로 답글 깊이에 제한이 없습니다. 게시판 API를 실행하려면 `FIREBASE_PROJECT_ID`, `FIREBASE_CLIENT_EMAIL`, `FIREBASE_PRIVATE_KEY` 환경변수가 필요합니다.

## 스티커와 관리자 설정

- 회원 메뉴는 자녀 모드로 시작합니다. 이름 오른쪽 자녀·부모 토글로 전환하며, 자녀는 스티커 수와 캐릭터 도감(`/catalog`), 부모는 회원 정보와 왼쪽 스티커관리·오른쪽 빨간색 로그아웃을 봅니다. 도감에서는 카테고리별 이미지와 이름을 60개씩 살펴봅니다.

- 이름퀴즈는 10문제 중 8개 이상 정답이면 3개, 사운드북은 같은 조건으로 1개를 자동 지급합니다. 같은 그림 찾기를 완료하면 1·2·3단계별 1·2·3개를 지급합니다. 10문제 미만의 복습은 퀴즈 보상을 지급하지 않습니다.
- 회원 메뉴의 스티커관리(`/stickers`)에서 지급 수량을 0~999개로 설정합니다. 기존 보유량은 유지하고 이후 획득부터 적용합니다.
- 첫 접속 시 숫자 6자리 관리자 암호를 두 번 입력해 설정합니다. 이후 암호 확인이 필요하며 5회 실패하면 잠기고 관리자 문의 알림이 뜹니다. 성공하면 실패 횟수를 초기화합니다.
- 현재 데이터는 계정별 서버 데이터가 아닌 이 브라우저 공용 localStorage(`hams-character-quiz:stickers:v1`)에 저장합니다. 암호는 salt를 사용한 PBKDF2 해시로 저장합니다. 로컬 데이터는 개발자 도구로 변경할 수 있으므로 실제 상점 결제 도입 전에 서버 검증과 DB 저장으로 전환해야 합니다.
